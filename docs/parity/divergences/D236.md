## D236 Go extensions read pig's launch and end startup with an exit status through the Host

What: a Pi extension runs in Pi's own Node process. It reads how Pi was started from `process.argv`, `process.stdin.isTTY` and `process.stdout.isTTY`, and it ends a misconfigured startup with `process.exit(code)`. A subprocess extension's argv, stdio and exit are its own process's. Pig adds two extension-wire calls and their Go SDK methods:

1. `ctx.HostLaunch()` (wire call `hostLaunch`, no arguments) returns `{"argv": string[], "mode": string, "stdinIsTTY": bool, "stdoutIsTTY": bool}`. `argv` is pig's command line after the executable, in order and unchanged, as Pi's `process.argv.slice(2)`; like Pi's, it holds a secret passed as an argument (`--api-key`). `mode` is the run mode `ctx.Mode()` reports (`tui`, `rpc`, `json` or `print`). The terminal flags are pig's stdin and stdout at launch, read before print, JSON and RPC mode replace `os.Stdout`. Nothing is read from the environment.
2. `ctx.ShutdownWithCode(code)` (wire call `shutdownWithCode`, `{"code": 0..255}`) is `ctx.Shutdown()` that ends pig with exit status `code`. In interactive and RPC mode it is Pi's `ctx.shutdown()` with that status: interactive mode stops when idle, RPC mode when its shutdown check runs (D231); a later stdin end or idle drain does not replace the status with 0. In print and JSON mode, where Pi ignores `ctx.shutdown()`, it aborts a run in progress, sends no further prompt, writes no result, disposes the runtime (`session_shutdown`) and exits with `code`. A request made in `session_start` sends no command-line prompt in any mode. Only a termination signal's status replaces `code`. The host rejects a missing or out-of-range code, and a host whose mode binds no handler rejects the call.

Not changed: `ctx.Shutdown()`, `ctx.Mode()`, the `PIG_HARNESS_ARGV_FILE` identity a Node extension's `process.argv` is built from, and the RPC and JSON mode wire formats. The two calls are new extension-wire calls; Node extensions keep Pi's `process.argv`.

Why: AIO's recipes port reads `--no-approve`, the explicit `-e` and `--models` flags and launch notes from argv, and stops a startup whose model scope matched nothing with exit status 1 before the command-line prompt reaches a fallback provider, which its TypeScript original does with `process.exit(1)`. `ctx.Shutdown()` has no status, is deferred in interactive and RPC mode, and is ignored in print mode.

Owner decision: requested by the task owner for the AIO Go extension (`go/aio/recipes.go`).

SCRUTINIZED:approved

Remove when: never as an API shape (a subprocess extension cannot read or end the host process); the record goes when the Rust, Python and Lisp SDKs expose the same calls and the capability moves to the cross-SDK ledger.
