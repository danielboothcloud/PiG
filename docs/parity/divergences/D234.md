## D234 Extensions share environment values with Node realms through the Host

What: Pi runs every extension and every Node provider in one Node process, so a value one extension writes to `process.env` is the value every other extension and provider reads next. Pig runs each extension in its own process, so a write to one process's environment reaches no other. Pig adds a Host-owned shared environment:

1. A native SDK sets or deletes one value: Go `ctx.SetSharedEnv(key, value)` and `ctx.UnsetSharedEnv(key)`, Rust `ctx.set_shared_env` and `ctx.unset_shared_env`, Python `ctx.set_shared_env` and `ctx.unset_shared_env`, Lisp `ctx-set-shared-env` and `ctx-unset-shared-env`. The wire call is `env.setShared` with `{"key": string, "value": string | null}`; `null` deletes the key.
2. Before the call returns, the Host queues an `env.shared` notification (`{"values": {key: string | null}}`) to every live Node realm, isolated or packed. The Node runtime applies it to `process.env` when the frame arrives, so the next request the Host sends any Node realm runs with the new value.
3. A Node realm that starts later inherits the values in its spawn environment, and receives a snapshot of every change when it connects. A deletion also removes a value inherited from pig's own environment.
4. The Host rejects an empty key, a key that contains `=` or NUL, a value that contains NUL, and keys that start with `PIG_EXT_` or `PIG_HARNESS_` (case-insensitive), which the Host owns.

Not changed: the environment of the pig process, of native (Go, Rust, Python, Lisp) extension processes, and of the processes the Host already started for other purposes. A Node extension's own `process.env` writes stay local to its process. The RPC and JSON mode wire formats are unchanged; the call and notification are new extension-wire messages.

Why: a Node provider written for Pi reads its switches from `process.env` at request time, for example `pi-cursor-sdk` reads `PI_CURSOR_EXPOSE_BUILTIN_TOOLS` to expose its bridge tools. A native extension that changes such a switch, as AIO's permission modes do when the mode changes, needs it to reach the provider unchanged. A documented event-bus channel would require every such provider to change.

Owner decision: requested by the task owner for the AIO Go extension (permission-modes Cursor bridge switch), with design (a) chosen over an event-bus channel because unchanged Node providers keep working.

SCRUTINIZED:approved

Remove when: Pig runs all extensions and providers in one shared environment, or Pi gains an equivalent API.

Call-site markers: `coding/extension/host/subprocess/shared_env.go`, `coding/extension/host/subprocess/runtime-node/runtime.mjs` (`env.shared` in `onEnvelope`), `extensions/sdk/context.go` (`SetSharedEnv`), `extensions/sdk-lisp/src/context.lisp`.

Evidence: `TestSharedEnvReachesNodeProcessEnvAcrossSDKs` and `TestSharedEnvRejectsInvalidAndHostOwnedKeys` (`test/extension-conformance/shared_env_test.go`, Go, Rust, Python and Lisp setters, isolated and shared cells, Node readers in an isolated cell and in a shared cell; red when the Node runtime does not apply `env.shared`), `TestSharedEnvAppliesToANewRealmsSpawnEnvironment` and `TestSharedEnvRejectsKeysBeforeRecordingThem` (`coding/extension/host/subprocess/shared_env_test.go`).

Parity allowance: none needed; Pi has no equivalent API, and a Pi extension never calls it.
